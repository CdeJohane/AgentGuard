  passed. The demo produced one executed read, three denials, and four records.

What I learned or explored:
- An agent can propose an action, while a separate guard checks permission.
- Default deny: an action is refused unless explicitly allowed.
- Fail closed: invalid input should be denied without crashing the guard.
- Valid input and permitted actions are different: a write request can be
  well formed and still forbidden.
- Python's 'and' short-circuits, so validation can protect later key lookups.
- Type annotations document expected inputs but do not enforce them at runtime.
- Used unittest assertions to check expected results automatically, including
  testing validation separately from permission decisions.
- Explored tuple unpacking and why a nonempty tuple containing False is truthy.
- Used ordered checks to choose a consistent reason when several rules fail.
- Explored an enforcement point: the execution function checks permission before
  calling an operation, so a denial actually prevents execution through that entry.
- Used mock-based tests to verify the reader is called once for allowed requests
  and never for forbidden or malformed requests.
- Separated making a permission decision from recording it: the audit function
  records the supplied allowed boolean and reason without checking permissions
  again. Initially found decision handling tricky, then completed the function.
- Used conditional expressions and short-circuit checks to extract audit fields
  safely. Fresh dictionaries preserve snapshots without copying extra data.
- Explored shared-state test isolation: setUp() and tearDown() clear the audit log
  so one test's records do not affect another test.
- Used integration tests to check the components together: the demo reaches the
  reader once, logs every attempt without contents, and starts fresh on each run.
